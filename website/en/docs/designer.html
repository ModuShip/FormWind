Designer and analyzers

FormWind works in the Visual Studio Designer — the in-process .NET Framework Designer and the out-of-process .NET 8+ Designer alike.

The Classes property

A TailwindProvider on the form adds Classes on tailwindProvider1 to every control's Properties window. The Designer writes your classes to Designer.cs as SetClasses calls, so they work with undo, source control and code review.

On .NET 8+ the field is a drop-down that suggests the theme's components and keeps your other classes (btn-ghost px-6 → btn-primary px-6). The multi-line "…" editor is available in the .NET Framework Designer.

Smart tag

Every control's smart tag — standard controls included — gets a FormWind section:

  • Classes and a Component list, plus quick picks suited to the control: button → btn-primary/btn-ghost/btn-danger, text box → input, panel → card, grid → table.
  • Class builder: drop-downs for colors (background, text, border), spacing and shape (padding, border, corners), typography (size, weight), and hover and dark-mode colors. Each field edits only its own group: choosing px-4 removes px-2 and pl-1 but keeps py-2.
  • Color lists start with your theme's own colors (brand-500 …); free text works too.
  • Unrecognized classes are listed as a warning; automatic classes show as AutoStyle: input.
  • Clear classes removes them all.

Preview and your theme

The Designer preview applies your classes, but properties the classes manage — BackColor, ForeColor, Font, Padding, Margin, Cursor — are not written to Designer.cs. Values you set by hand that the classes don't manage still are.

The package's build/FormWind.targets embeds tw.config.json from the project folder into the application's assembly. The Designer finds the assembly of the form being designed and reads the theme from its folder (fonts and SVG icons included) or the embedded copy, so the preview and the lists use your theme. After changing the theme file, build and reopen the form.

<PropertyGroup>
  <FormWindThemeFile>Themes\tw.config.json</FormWindThemeFile>   <!-- a file elsewhere -->
  <FormWindEmbedTheme>false</FormWindEmbedTheme>                 <!-- turn embedding off -->
</PropertyGroup>

At run time the application still loads the file with TwTheme.LoadIfExists; only the Designer reads the embedded copy.

TwTabControl

"Add page" and "Remove selected page" commands; clicking a tab at design time switches pages; controls dropped on the control land on the current page.

FW001: assignment conflicts with classes

The analyzer shipped in the package warns when code assigns a property the control's classes manage:

tw.SetClasses(btnSave, "btn-primary");
btnSave.BackColor = Color.Red;   // FW001: 'btnSave' has classes; assigning 'BackColor' conflicts with them.

At run time a color assignment wins — FormWind leaves that channel to the application — so the warning can be suppressed for deliberate status colors. Padding and margin assignments are undone (see DPI), so there the warning points to a real conflict. Only constant class strings and properties the classes actually manage are checked.

FW002: forms that won't scale

In .NET Framework projects, warns when an InitializeComponent that uses SetClasses sets AutoScaleMode.Font and assigns the form's Font after AutoScaleDimensions. Under PerMonitorV2 such a form doesn't scale; the fix is AutoScaleMode.Dpi (see DPI).

# .editorconfig
dotnet_diagnostic.FW001.severity = none
dotnet_diagnostic.FW002.severity = none
