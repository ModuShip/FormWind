Accessibility

Owner-drawn controls expose their items to screen readers and automation tools, High Contrast mode is respected, and a contrast audit checks your light and dark themes against WCAG.

Screen readers and UI Automation

FormWind's owner-drawn controls work with Narrator, NVDA, FlaUI and Appium/WinAppDriver:

ControlRoleItems
TwDataListListEach row is a ListItem, named by AccessibleItemText or ItemText; created on demand.
TwTabStripPageTabListEach tab is a PageTab with its selected state.
TwCalendarTablePrevious/next month buttons and days ("15 October 2026 Thursday").
TwSelectComboBoxThe value is the selected item; the default action opens the menu.
TwSlider, TwProgressSlider, ProgressBarValue.
TwTreeViewOutlineOutlineItems with expanded state and level.
TwPager, TwToast, TwDialogToolBar, Alert, Dialog"Page 3 of 20".

Selection and focus changes are announced. Give fields without a visible label an AccessibleName; inside a TwField the label is used automatically. All controls are fully keyboard-operable, and focus-visible: rings show only for keyboard focus. Native parts FormWind draws in place of Windows (the tab strip, disabled text, the dark DropDownList box, disabled lists) keep name, role, state and value; they draw the focus rectangle they cover while keyboard cues are on.

High Contrast

When a Windows contrast theme is on, FormWind uses system colors instead of class colors:

  • Backgrounds and text return to their system values; selected and hovered parts get the highlight color.
  • Borders and separators are drawn in the text color; shadows, gradients and transitions are not drawn. Borderless TwButtons get a 1 px border.
  • Spacing, font size, corners and layout stay. Styles are reapplied when the mode changes.
  • Use forced-colors: for colors specific to this mode, as in Tailwind: forced-colors:border-2.
  • Opt out with RespectHighContrast = false; read the state from HighContrastActive in code that draws itself.
  • What FormWind draws in place of Windows returns to Windows: the tab strip, ProgressBar colors, dark scrollbars, the list theme and tooltips, the title bar's dark mode and colors, LinkLabel link colors, the PropertyGrid glyphs. Redrawn disabled text is GrayText.

Windows text size

Windows' Text size setting (100–225%) multiplies text-* sizes like rem in a browser; spacing stays, and fixed-size buttons trim their padding so the text fits. Styles are reapplied when the setting changes. Turn it off with TwFonts.RespectTextScale = false.

Contrast audit

TwContrast checks a form's current colors against WCAG 2 ratios — 4.5:1 for normal text, 3:1 for large text. Run it in tests or during development, in both modes:

tw.DarkMode = true;
foreach (var issue in TwContrast.Audit(this, tw))
    Debug.WriteLine(issue);   // TwButton 'btnSave' hover: 2.54:1 < 4.5:1 (#FFFFFF on #60A5FA)
  • Checks text controls, hover: variants (no mouse needed), strips and menus, and DataGridView cells, selection and headers.
  • Transparent backgrounds are blended with the parent's; hidden controls are skipped. includeDisabled: true also checks disabled controls; for buttons, check boxes and labels whose text FormWind redraws, the color actually drawn is checked against 3:1 (see Disabled text).
  • The link color of a LinkLabel is checked as the link part.
  • issue.Cause gives a known cause: TwContrastCause.KeptBackground when the classes give only the text color and the background stays a color the application set explicitly, different from the parent's. The fix is a bg-* class or letting copied backgrounds follow the parent; ToString() mentions the cause too.
  • Colors mid-transition are checked at their target, so the audit can run right after a theme change.
  • TwContrast.Ratio(foreground, background) returns the ratio between two colors.
  • TwContrast.FindOwnerDrawn(root) lists controls that paint their own colors, which the audit can't see — check those by eye.

The default components and every preset pass this audit in light and dark mode, with both palettes.
