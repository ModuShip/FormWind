Tools

Move an existing application to classes, try FormWind on it without touching its source, and explore the samples.

Converter

tools/FormWind.Convert turns hard-coded style assignments in Designer files into classes. The default is a dry run that prints what would change:

dotnet run --project tools/FormWind.Convert -- src/MyApp --report conversion.md
dotnet run --project tools/FormWind.Convert -- src/MyApp --audit --report audit.md
dotnet run --project tools/FormWind.Convert -- src/MyApp --write
Designer lineClass
BackColor / ForeColorbg-* / text-*: the palette color, the nearest one within 10 units (with a note), otherwise bg-[#hex]
Fonttext-sm … text-4xl or text-[13px]; Semibold/Bold → font-semibold/font-bold; italic, underline
Paddingp-*, px-*/py-* or per side
FlatAppearanceborder-0/border, border-*, hover:bg-*, active:bg-*
  • Converted lines are replaced by a SetClasses call; a TailwindProvider is added (and disposed with the form) if the file has none.
  • C# and Visual Basic (.Designer.vb), old and new Designer formats, and controls generated as local variables are supported.
  • System colors, your own color expressions, derived fonts and other font families are left in place and listed in the report; a control with nothing converted is marked (nothing converted).
  • A second run leaves the files alone ("nothing to change"); BOM and line endings are kept.
  • Pre-migration audit: --audit lists, without touching the files, the places to look at by hand after FormWind is added, with file:line and a suggestion: colors assigned in code, list item and tree node colors, grid cell styles, controls that draw themselves, fixed-size buttons with images, SetWindowTheme and loading RTF. Code outside the Designer files is scanned too. On KeePass 2.61.1 it listed everything the manual integration had found from screenshots.
  • --config tw.config.json matches against your own palette; --tolerance changes the nearest-color threshold.
  • Verified on Git Extensions (74 Designer files, 360 classes) and Greenshot (311 controls): the converted projects built without warnings, with identical colors and fonts.

--write updates files in place. Commit first.

Harness

tools/run-harness.ps1 runs a .NET WinForms application with FormWind applied to every form — without changing its source code — and records what happens:

.\tools\run-harness.ps1 -Exe C:\apps\MyApp.exe -SelfTest -ExitAfter 60
OptionEffect
-DarkStarts in dark mode. Ctrl+Alt+Shift+D toggles the theme while running.
-SelfTestCaptures every new form in light and dark mode and audits its contrast from the class colors and from the image.
-ExitAfter 60Ends the process after 60 seconds, for unattended runs. The countdown runs on a background thread, so the process ends even when UI timers stop.
-Skip DataGridView,ToolStripLeaves these types unstyled, to narrow a problem down.
-DumpApplies nothing; writes each form's colors, fonts and padding — compare before and after the converter.
-Dpi 144Scales every form, after styling it, as if moved to a 144 DPI screen (PerMonitorV2 applications only). -Dpi screen moves the form to a real screen with another DPI.
FORMWIND_MENU=m_menuToolsOptionsClicks the menu items with these names on the first form one by one and processes and closes the forms they open; for reaching dialogs opened from menus without supervision.
FORMWIND_DISABLE=1Turns the harness off, to reproduce a problem without FormWind.

The log in %TEMP%\FormWind-Harness\ lists styled forms, contrast problems (CONTRAST, SCREEN), owner-drawn controls to check by eye, UI stalls over 250 ms, paint storms, exceptions and unknown classes. TIMER STARVATION reports that the UI thread processes messages but WinForms timers have not ticked for 2 seconds (a window invalidating itself on every paint), UI BLOCKED that no message is processed at all. When the application's error dialog opens, the first lines of the error are logged too.

Forms that already use FormWind (a TailwindProvider field on the form, or a form styled by TwAutoTheme) are not restyled; the harness audits them and switches the theme through the application's own provider.

  • The harness is a .NET startup hook. For .NET Framework applications, add FormWindHarness.cs (LangVersion latest) and FormWind's net472 build to the project, turn on AutoGenerateBindingRedirects and call FormWindHarness.Install() at the start of Main. Without a message loop Install creates no window; the harness is installed when the first form opens.
  • In applications that open windows on separate UI threads, the harness is installed on each thread; the theme shortcut reaches all of them.
  • Tried on Git Extensions, Greenshot, mRemoteNG, the Krypton Toolkit samples, the ScottPlot WinForms demo, an MDI shell, ShareX, KeePass, Open Live Writer, Bulk Crap Uninstaller (ObjectListView), the AdvancedDataGridView sample and a business form (master-detail grids, validation). For applications that load for a long time at startup, FORMWIND_SELFTEST_DELAY=30000 delays the first capture.

Benchmarks

tools/FormWind.Benchmarks builds the same form with plain WinForms, FormWind, Krypton Toolkit and MaterialSkin.2 and measures time, memory and GDI/USER objects. The results are on the Performance page.

Building from source

build.ps1 runs the same steps as CI — build, tests on four targets, coverage, packing. -Quick builds and tests on .NET 8 only.

.\build.ps1

This website is built with website/build.ps1; -Reference also renders the class reference with real controls.

.\website\build.ps1 -Reference
