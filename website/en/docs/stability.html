Versioning and API stability

FormWind is in preview (0.x). Minor versions may still contain breaking changes, and each one is listed under Changed or Removed in the changelog. Three contracts are tracked separately, so you can tell what an upgrade may touch.

Public API

TailwindProvider, the controls, TwTheme, the presets, the events and the classes form the public API. Every public member of both packages is listed in PublicAPI.Shipped.txt and PublicAPI.Unshipped.txt, and the build warns when a member is added or removed without updating them. Helpers used only by the library, including the Designer types, are internal.

From 1.0, changes follow Semantic Versioning:

VersionMay contain
Major (2.0.0)Removed or changed public members, class meanings that change the look of existing forms, a dropped target framework.
Minor (1.1.0)New classes, controls, members or options; existing code and forms keep working the same.
Patch (1.0.1)Bug fixes without API changes. Rendering changes only where the previous rendering was clearly wrong.

After the first stable release, package validation checks binary compatibility against the previous version.

Class syntax

What a class means is pinned by tests that do not compile against it. tests/FormWind.Tests/Golden/parse.txt holds the resolved style of about 70 sample class strings, with their variants, parts, presets and the v4 palette:

"bg-red-600/50 text-gray-900/75"
  BackColor = #80DC2626
  ForeColor = #BF111827

GoldenParseTests fails when one of them changes. An intended change is recorded with FORMWIND_UPDATE_BASELINES=1 and listed in the changelog, so bg-blue-500 on your form does not change color by accident.

Theme file

"version" in tw.config.json is the file format version: TwTheme.FileVersion, currently 1. A file without it is version 1. A file written for a newer format is rejected with NotSupportedException instead of being read wrongly.

{ "version": 1, "preset": "fluent" }

Experimental extension points (FW9001)

Some extension points are tied to System.Drawing and WinForms types and may change when the platform-neutral core is extracted:

  • IStyleApplier, TwApplyContext, TwAppliers, WinFormsApplier
  • TwStyle, TwParsed, TwOriginal, TwTheme.Parse
  • Helpers that take a TwStyle: TwFonts.Create, TwChrome.FromStyle, TwGradient.FromStyle, TwLayout.Apply, TwToolTip.ResolveStyle

They are marked [Experimental]: using them is a compile error (FW9001) until you suppress it, which records that you accept they may change.

<PropertyGroup>
  <NoWarn>$(NoWarn);FW9001</NoWarn>
</PropertyGroup>

Applications that only use classes, presets, the theme file and the controls never see FW9001. You need it when you write your own applier for another control library (see other control libraries).

Known limitations

  • Controls that draw their own cells (for example owner-drawn grids) ignore cell styles and may stay light in dark mode; TwGrid.EnableDarkInversion helps for some of them.
  • The multi-line Classes editor window is only available in the .NET Framework Designer; the .NET 8+ Designer has the drop-down and the class builder.
  • Some owner-drawn controls are not mirrored for right-to-left yet (see Right-to-left).
