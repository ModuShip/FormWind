DataGridView

The grid is styled with part prefixes that combine with state prefixes (dark:header:bg-gray-900, row:hover:bg-gray-50). The table component gives a light and dark table in one class.

tw.SetClasses(gridOrders, "table");

The showcase sample's grid form (FormWind.Showcase --grid): search, filter menu, grouping, totals, row details, the new cell types and saving the layout.

tw.SetClasses(gridOrders,
    "bg-white text-gray-800 divide-y divide-gray-100 cell:px-3 row:h-10 row:hover:bg-gray-50 "
  + "header:bg-gray-50 header:text-gray-500 header:font-semibold header:text-xs row-header:hidden "
  + "selected:bg-blue-50 selected:text-blue-900 "
  + "dark:bg-gray-900 dark:text-gray-100 dark:header:bg-gray-800 dark:selected:bg-blue-950");
  • Header colors turn off EnableHeadersVisualStyles, which would otherwise ignore them.
  • row:h-* on bound or VirtualMode grids uses RowHeightInfoNeeded: rows stay shared and scrolling and selection are kept (about 12 ms for 17,000 rows).
  • Removing the classes returns the grid to its original styles.
  • Grids that paint their own cells ignore cell styles; divide-* and row:h-* change structural properties, so check such grids before using them.
  • table variants go after it: table-sm (32 px rows), table-lg (48 px rows), table-striped, table-bordered. Fluent, Ant Design and Material define their own heights.
  • TwGrid.EnableDarkInversion(grid) gives self-drawing grids a dark mode: the grid is styled light and its picture is inverted with the hue kept, so hard-coded light colors turn dark too.

Column classes

Every column gets a ColumnClasses on tailwindProvider1 property in the Designer (SetColumnClasses in code). Base classes apply to the cells, header: to the header; w-32, min-w-20, flex-1 (fill weight) and hidden affect the column itself.

tw.SetColumnClasses(colTotal, "text-right font-semibold w-28 header:text-right");
tw.SetColumnClasses(colName, "flex-1 min-w-40");

Cell types learn dark mode from the grid's provider; dark: variants need no extra setup.

Row rules

tw.SetRowClasses(gridOrders, row =>
    row.Cells["colStatus"].Value as string == "Cancelled" ? "text-gray-400 dark:text-gray-500" : null);

The rule returns classes for each row (null = no change). It runs during CellFormatting, so it updates itself when the data changes. SetRowClasses(grid, null) removes it.

Sorting, empty and loading states

gridOrders.DataSource = new TwSortableBindingList<Order>(orders);
TwGrid.SetEmptyText(gridOrders, "No orders found");   // icon + text when there are no rows
TwGrid.SetLoading(gridOrders, true);                  // skeleton rows, or a dimmed overlay with "Loading…"

A grid bound to a List<T> doesn't sort on header clicks; TwSortableBindingList<T> does, with culture-aware, stable sorting. The sort arrow is drawn with the theme's icons and accent-* color.

Filtering and paging

TwGrid.EnableFilterMenu(gridOrders);     // a filter button in each header: values with check boxes
TwGrid.EnableColumnChooser(gridOrders);  // right-click a header to show or hide columns
  • The filter menu appears on grids whose data source is an ITwFilterableList (such as TwSortableBindingList<T>) and on columns with a DataPropertyName. In code: list.SetColumnFilter("City", new[] { "Izmir" }), ClearFilters().
  • Sorts stack, and filtering keeps the sort order.
  • Columns with eight or more values get a search box in the menu; number and date columns of a TwSortableBindingList<T> get Min/Max boxes (list.SetRangeFilter("Amount", 100, null)).

TwPager draws paging buttons (‹ 1 … 9 10 11 … 20 ›); you bind the page:

pager.TotalItems = orders.Count;
pager.PageSize = 20;
pager.PageChanged += (s, e) => grid.DataSource = orders.Skip(pager.FirstItemIndex).Take(pager.PageSize).ToList();
tw.SetClasses(pager, "text-gray-700 selected:bg-blue-600 selected:text-white item:hover:bg-gray-100");

Search

TwGrid.AttachSearchBox(gridOrders, txtSearch);   // searches as the user types; Escape clears
TwGrid.SetSearchText(gridOrders, "izmir");        // in code

Matches are highlighted with the match: colors. A TwSortableBindingList<T> keeps only the matching rows, an unbound grid hides the others, other bound grids only highlight.

Grouping and totals

TwGrid.SetGroupBy(gridOrders, colCity);           // header with the row count; click to collapse
var footer = TwGrid.AddFooter(gridOrders);
footer.SetText(colCustomer, "Total");
footer.SetAggregate(colAmount, TwAggregate.Sum, "C2");   // Sum, Average, Count, Min, Max
  • The list orders rows by the group and keeps the sorting within groups; with other sources consecutive equal values form a group.
  • The footer follows column widths, order and horizontal scrolling, and counts only the shown rows.

Row details

gridOrders.Columns.Insert(0, new TwExpanderColumn());
TwGrid.SetRowDetails(gridOrders, row => new OrderLinesView((Order)row.DataBoundItem), height: 160);

The control appears below the expanded row and moves with scrolling; expanded rows survive sorting and filtering.

Layout and export

var layout = TwGrid.SaveLayout(gridOrders);   // JSON: columns, sorting, grouping, search, filters
TwGrid.LoadLayout(gridOrders, layout);
TwGrid.ExportCsv(gridOrders, path);           // UTF-8 with BOM, the culture's list separator
TwGrid.CopyToClipboard(gridOrders);           // selected cells as tab-separated text

Large tables

TwVirtualRows<T> puts the grid in VirtualMode and loads rows page by page as they come into view, caching recent pages. With a million rows only the visible pages are in memory.

var rows = new TwVirtualRows<Order>(gridOrders,
    (start, count) => db.Orders.OrderBy(o => o.Id).Skip(start).Take(count).ToList(), pageSize: 100);
rows.Reset(db.Orders.Count());   // again when the data or the sort order changes
  • Cell values come from the property named by the column's DataPropertyName (or its name); override with rows.CellValue.
  • The loader runs on the UI thread — keep it fast (OFFSET/FETCH in the database). Sort in the query and call Reset.
