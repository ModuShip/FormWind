Utility classes

Classes follow Tailwind's names and map to WinForms properties — or to painting where WinForms has no property. The class reference shows each one rendered on a real control.

  • The spacing unit is 4 px (spacingUnit in the theme). Numbers always use a dot, in every culture: p-0.5.
  • Every color class takes an opacity: bg-black/50, text-white/75.
  • Within the same variant the later class wins: p-2 px-4 → 8 px vertical, 16 px horizontal.
  • Unknown classes are reported through TailwindProvider.UnknownClasses (or the Debug output when nobody listens).

Variants

A prefix applies a class only in a state. Prefixes combine: dark:hover:bg-gray-800.

VariantApplies when
hover:, active:The mouse is over the control / the button is pressed.
focus:, focus-visible:The control has focus / focus came from the keyboard (Tab, arrows), not a click.
disabled:Enabled is false. focus, hover and active do not apply then.
checked:A check box, radio button, switch or check button is checked.
invalid:The control has a validation error (Forms).
group-hover:The mouse is over a container with the group class.
dark:TailwindProvider.DarkMode is on.
sm: … 2xl:The form is at least 640 / 768 / 1024 / 1280 / 1536 px wide (responsive).
rtl:, ltr:The control's inherited RightToLeft direction.
forced-colors:Windows High Contrast is on (accessibility).

Variant order

Later overrides earlier:

base → dark: → checked: → focus: → focus-visible: → group-hover: → hover: → dark:hover: → active: → disabled: → invalid: → sm: → md: → lg: → xl: → 2xl: → forced-colors:

disabled: takes precedence over dark:. Give your own components dark:disabled: colors for dark mode as well — the default btn-primary, btn-ghost and btn-danger do.

Shadows and rings are drawn on the control's parent — controls cannot paint outside their bounds — on Form, Panel and TwPanel parents. That is how native controls such as TextBox get a focus ring.

Gradients

bg-gradient-to-{r,l,t,b,tr,tl,br,bl} from-{color} via-{color} to-{color} — painted on TwPanel, TwButton and the standard Panel. A missing end is the transparent version of the other end.

tw.SetClasses(pnlHero, "bg-gradient-to-r from-sky-500 to-indigo-500 text-white rounded-xl p-6");

Interaction

  • transition (transition-colors, duration-75 … duration-1000, duration-[250ms]) fades background, text and shadow changes (ease-out, 150 ms by default). The first application has no transition: when classes are assigned, the control takes its final color at once; theme, state and class changes are animated.
  • hover: / active: restyle only controls that use these variants; other controls ignore mouse movement.
  • group / group-hover: style children when the container is hovered — even when the cursor enters through a child.
  • Placeholders: TwTextBox.PlaceholderText, colored with placeholder:text-gray-400.
  • focus-visible: also governs the focus rings of owner-drawn controls. TwFocusVisible.LastInputWasKeyboard tells which input came last.
tw.SetClasses(cardOrder, "group card transition hover:shadow-lg");
tw.SetClasses(lblOrderTitle, "font-semibold group-hover:text-blue-600");
tw.SetClasses(txtName, "input focus-visible:ring-2 focus-visible:ring-blue-500/40");

Colors your code assigns

If application code changes a control's BackColor or ForeColor after classes were applied — a status indicator painted green, say — FormWind leaves that channel to the application. hover:, dark: and other variants no longer override it; the other channel stays with FormWind.

tw.SetClasses(lblStatus, "bg-white text-gray-700 dark:bg-gray-800 dark:text-gray-200");
lblStatus.BackColor = Color.LightGreen;            // stays green in dark mode; text color still from classes
tw.SetClasses(lblStatus, "bg-red-600 text-white"); // new classes: the background is FormWind's again
  • Colors inherited from the parent (the form switching to dark mode) do not count as assignments.
  • To give the channel back, assign different classes; Refresh(control) is not enough.
  • The contrast audit reports unreadable pairs this can produce in dark mode.
  • The FW001 analyzer flags such assignments at compile time.

Colors for painting code

Where the application paints the colors itself (a CellPainting handler, an owner-drawn ListView), ask the provider for the class colors. The result follows the provider's current mode (dark, high contrast); a color the classes do not set is null.

var selected = tw.GetColors("list", "selected");            // components and parts are expanded
var hover = tw.GetColors("list", "item", TwState.Hover);
var own = tw.GetCurrentColors(lvUploads, "selected");          // the control's classes and current state
e.Graphics.FillRectangle(new SolidBrush(selected.Back ?? SystemColors.Highlight), e.Bounds);

Removing classes

SetClasses(control, "") restores color, font, padding, margin, cursor, visibility, corners and the ToolStrip renderer to their values from before the classes. Sizes (w-*, h-*) are not reverted, because the layout may have resized the control since.

WinForms differences

  • Padding on fixed-size controls. In CSS padding grows the box; on a WinForms button or label with AutoSize off it shrinks the content. FormWind reduces padding just enough for the text to fit on one line and restores it when there is room. It cannot shrink the font, so avoid font classes on controls too small for them.
  • Corners on standard controls are clipped with a Region, without anti-aliasing. Use TwButton, TwPanel and TwTextBox for smooth corners.
  • Text boxes get border-* and rounded-* as a frame drawn on the parent, 3 px outside the control. Leave room in the layout.
  • Disabled native text boxes: TextBox and MaskedTextBox keep the classes' background (Windows draws the text in the system gray). A disabled RichTextBox ignores its background, so it only takes disabled: colors; otherwise Windows keeps its own look.
  • Disabled buttons are redrawn with disabled:text-* — or the text color mixed halfway toward the background — instead of Windows' darkened text, which disappeared on dark backgrounds.
  • MDI: the container form's bg-* also colors the area behind the child windows.
  • Boxes in strips (ToolStripTextBox, ToolStripComboBox) take colors derived from the strip, so they don't stay white on a dark toolbar.

Errors

Styling never crashes the application. An exception while applying styles is caught, the control keeps the style applied so far, and the error is reported through StyleError (or the Debug output). The control is retried on its next state change. Critical exceptions such as out-of-memory are not caught.

tw.StyleError += (s, e) => logger.LogWarning(e.Exception, "Could not style {Target}: {Classes}", e.Target, e.Classes);
tw.UnknownClasses += (s, e) => Debug.WriteLine($"{e.Control.Name}: {string.Join(" ", e.Unknown)}");
