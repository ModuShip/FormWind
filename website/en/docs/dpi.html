DPI

Class values are in 96-DPI pixels and scale with the control's DeviceDpi: p-2 is 8 px at 100% and 10 px at 125%.

Recommended setup

  • Forms: AutoScaleMode = AutoScaleMode.Dpi and AutoScaleDimensions = new SizeF(96F, 96F). For forms built in code, wrap the constructor in SuspendLayout/ResumeLayout.
  • Process: PerMonitorV2.
// .NET 8+, Program.Main
Application.SetHighDpiMode(HighDpiMode.PerMonitorV2);
SetupResult
DPI-unaware (the .NET Framework 4.7.2 default)Windows scales the bitmap; the layout is right, the text blurry. No extra setup needed.
PerMonitorV2 + AutoScaleMode.DpiLayout, fonts and FormWind spacing scale together.
PerMonitorV2 + AutoScaleMode.FontOn .NET Framework, Designer forms whose Font is assigned after AutoScaleDimensions don't scale: spacing and fonts grow, controls don't.

.NET Framework notes

  • Enable PerMonitorV2 with DpiAwareness in the System.Windows.Forms.ApplicationConfigurationSection of app.config. Keep the build's bindingRedirects when editing it, or System.Text.Json can't load.
  • PerMonitorV2 only takes effect when the application manifest declares Windows 10 compatibility (supportedOS).
  • If your code creates a Font in Program.Main before any form, call new Control().Dispose() first so GDI+ doesn't stay at 96 DPI.
  • The AutoScaleMode.Font problem above also happens without FormWind, cannot be fixed at run time, and is flagged by the FW002 analyzer.

Moving between screens

When a form moves to a screen with a different DPI, FormWind reapplies classes once after WinForms finishes scaling. With AutoScaleMode.Dpi, fonts, spacing, owner-drawn controls and DataGridView fonts and column widths scale correctly — verified at 150% and 200%.

Double scaling

SetClasses in InitializeComponent assigns a scaled value, which the form's AutoScale would scale again (8 → 10 → 12 px at 125%). FormWind prevents this:

  • When the classes define padding or margin, FormWind's value is written back whenever it changes.
  • Classes are reapplied once when the control's handle is first created — after scaling, before Load.

As a result, while classes manage padding or margin, run-time assignments to them are undone (FW001 warns). Remove padding and margin from the classes to keep your own values.

If the application is DPI-aware but its forms' AutoScale doesn't enlarge the layout, spacing grows while controls don't. Fix AutoScale, or set TailwindProvider.ScaleWithDpi = false.
