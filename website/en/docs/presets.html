Presets and AutoStyle

Pick a preset and turn on AutoStyle: every control on the form gets the component that matches its type. No classes, no Designer changes.

// tw.config.json
{ "preset": "fluent" }   // tailwind (default), fluent, antd, material
tailwindProvider1.AutoStyle = true;   // Designer: Properties → FormWind → AutoStyle

Presets

A preset (TwPreset; in code new TwTheme(TwPreset.Fluent)) sets the colors, the fonts and the shape of the components — corners, spacing, weight.

  • The looks are inspired by the named design systems. They are not those systems and contain no logos or assets.
  • Where an original color fails WCAG AA, it is darkened: Ant Design's #1677ff gives 4.1:1 with white text, so filled buttons use primary-600 (#0958d9).
  • Fluent uses Segoe UI Variable on Windows 11; Material uses Roboto when installed. Both fall back to Segoe UI.
  • Every preset passes the contrast audit and the visual regression tests in light and dark mode.

Components

All presets define the same component names, so switching presets restyles the whole application without touching its classes or Designer.cs.

Semantic colors

Components use five semantic colors: primary, surface (neutral backgrounds and text), danger, success and warning — as in bg-primary-600 or text-surface-500. In the default theme they copy blue, gray, red, green and amber.

Defining a ramp in the theme file recolors every component at once. Use the semantic names in your own classes and they change with the preset too.

{
  "preset": "antd",
  "colors": {
    "primary": {
      "50": "#eef2ff", "100": "#e0e7ff", "200": "#c7d2fe", "300": "#a5b4fc", "400": "#818cf8", "500": "#6366f1",
      "600": "#4f46e5", "700": "#4338ca", "800": "#3730a3", "900": "#312e81", "950": "#1e1b4b"
    }
  }
}

Customizing a preset

The theme file is applied on top of the preset; write only what differs — a primary ramp, your own btn component. To change a preset throughout, copy its file from src/FormWind/Presets/ as tw.config.json; the files use the same format. See Theme file.

AutoStyle

While TailwindProvider.AutoStyle is on, the controls of the ContainerControl form get the component mapped to their type — including controls added later. In the Designer, ContainerControl is set to the form itself (as with ErrorProvider); in code, write provider.ContainerControl = this;.

  • Labels and panels are not listed: they take the form's text and background colors.
  • A control's own classes are added on top of the automatic component, so flex-1, mt-2 or bg-red-50 keep the look. When its own classes name a component (btn-primary, card …), the automatic one is not used.
  • Automatic classes are not written to Designer.cs. The smart tag shows them as AutoStyle: input.
  • LinkLabel is not mapped (it draws links with LinkColor); use a Label with the link component.
  • Composite controls (the text box inside TwTextBox, NumericUpDown, PropertyGrid) are not entered.

Changing the mapping

The key is the short type name; base types are searched too (TextBoxBase covers every text box). An empty value leaves that type unstyled.

{
  "autoStyle": { "Button": "btn-primary", "Label": "muted", "KryptonButton": "btn-ghost", "ListView": "" }
}
theme.SetAutoStyle("Button", "btn-primary");

The showcase has a form that switches between presets: FormWind.Showcase.exe --presets (add --preset fluent for the initial one).
